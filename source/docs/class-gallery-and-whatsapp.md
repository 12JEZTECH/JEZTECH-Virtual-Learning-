# Class camera gallery and WhatsApp contact

Students see the current teacher and classmates in the live classroom. On desktop, live cameras and controls appear in a side panel alongside notes and clips; on phones, the panel moves above materials. The teacher tile is first and names remain available when cameras are off. Existing class roster, teacher presence, subject exemptions, active-assessment restrictions and access expiry checks remain authoritative.

Small group mode uses authorized peer video links for up to ten audience connections. A deterministic offerer prevents simultaneous student video offers. Teacher links retain the existing moderated group audio mixer. Student-to-student session descriptions cannot include audio, so those video links do not bypass teacher microphone controls. Participants select Share my camera with this class before joining; no device capture starts automatically. Direct peer connections may require the existing configured TURN service on restricted networks.

Large-class mode uses LiveKit. Eligible learners receive camera publishing permission while microphone sources remain individually approved and bounded to eleven learner speakers. Learners cannot publish screens, room data or change metadata. Camera tracks publish only after the learner clicks Share my camera with class and permits browser access. The teacher stays in the gallery while pages select eleven other participants, limiting camera subscriptions; audio uses the existing moderation policy. Provider capacity and network bandwidth must support the actual intended audience. Multi-device camera quality and 500 simultaneous publishers have not been load-tested in production.

A global WhatsApp contact button opens https://wa.me/254713539260 for the user-specified number +254 713 539 260. It opens a new tab without sending any message, pre-filling private learner data or opening WhatsApp automatically. It does not forward the class chat or establish a video conference.

Automated coverage checks scoped student video signaling, rejection of unmoderated peer audio, deterministic offer roles, pinned/paged gallery membership, authoritative recipient access revocation, and LiveKit camera-only versus camera-plus-approved-microphone permissions. Existing 600-participant authorization checks retain their bulk-query and speaker-cap assertions. Live multi-device media verification requires signed-in participants and their camera consent.
